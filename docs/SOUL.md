# Portfolio OS Soul

Date: 2026-08-11

Status: Approved product character

## Emotional North Star

The portfolio should feel like opening a beautifully made operating system belonging to a thoughtful platform engineer: tactile, capable, slightly unexpected, and immediately understandable.

The visitor should think:

- Ben cares about the paths other engineers use.
- Ben can make complex systems feel clear.
- Ben has strong technical judgement and a point of view.
- This is playful, but the work behind it is serious.

## Personality Balance

- 70% professional confidence
- 20% curiosity and craft
- 10% mischief

The interface carries most of the personality. The written copy stays direct.

## Product Worldview

Platform engineering is not presented as a collection of infrastructure tools. It is presented as the work of removing friction, creating dependable interfaces, improving feedback loops, and helping teams deliver with confidence.

The operating-system metaphor supports that worldview. Windows are bounded contexts. The dock is a paved road. Applications expose focused capabilities. The command interface is an optional expert path. The Career application turns a timeline into a system the visitor can actively inspect.

## Recruiter Contract

The site may be unusual, but it must never be difficult.

Within ten seconds, a recruiter must be able to identify:

- Ben Hutchinson
- Mid-level platform engineer
- Manchester, UK
- Backend foundations with a platform-engineering trajectory
- Migrated 50+ repositories and reduced average build time by four minutes
- Clear routes to work, career, CV, GitHub, LinkedIn, and contact

The operating-system interaction is an invitation, not an entrance exam. No important evidence may depend on knowing terminal commands, dragging a window, completing an animation, or discovering a hidden control.

## Interface Personality

The interface is:

- Tactile
- Crisp
- Optimistic
- Tool-like
- Fast
- Slightly irreverent
- Precise about state

The interface is not:

- A fake hacker terminal
- A nostalgic desktop replica
- A game that delays the portfolio
- A stock dashboard
- A chaotic pile of overlapping windows
- A sci-fi command centre
- A space theme with professional content attached afterward

## Visual Character

The approved visual language combines:

- Mint desktop surfaces
- Warm off-white application chrome
- Near-black ink borders and hard shadows
- Signal orange for emphasis and state
- Warm yellow for active controls
- Occasional sky blue for a career stage
- Monospace interface labels
- Bold grotesk display type for outcomes and headlines

The result should feel designed, not themed. It can reference operating systems without imitating macOS, Windows, Linux, or a specific historical era.

## Motion Character

Motion should feel mechanical and responsive:

- Windows lift, focus, minimize, and maximize.
- Dock items acknowledge hover and activation.
- Career stages snap decisively into place.
- Colour and typography transform with the career scrubber.
- Small transitions communicate state changes.

Motion must never create artificial waiting. There is no boot sequence, loading theatre, autoplay tour, continuous background animation, or mandatory intro.

Reduced-motion mode replaces spatial transitions with immediate state changes while preserving every interaction and piece of content.

## Writing Voice

Copy is:

- Plain-spoken
- Specific
- Outcome-led
- Technically credible
- Confident without exaggeration
- Short enough to scan

Prefer:

- Migrated 50+ repositories and reduced average build time by four minutes.
- I remove friction from delivery.
- Building reliable paths for engineering teams.

Avoid:

- Passionate ninja, rockstar, guru, or wizard language
- Empty claims such as world-class, cutting-edge, or revolutionary
- Dense autobiographical paragraphs
- Tool inventories presented as identity
- Inflated scale or unverified business outcomes

## Interaction Standard

Every interaction must do at least one of three things:

1. Reveal evidence.
2. Explain a relationship.
3. Help the visitor navigate.

If an interaction only decorates the page, remove it or make it extremely subtle.

## Personal Signature

The terminal, desktop icons, draggable windows, and small system labels provide charm. They should reward exploration with concise details and optional humour, but never remix professional evidence into jokes.

Small personal easter eggs may appear later as optional desktop details. They are not part of the core information architecture and must not compete with Ben's work.

## Decision Rule

When choosing between spectacle and clarity, preserve both by making clarity the default and spectacle the enhancement.

When choosing between more features and a more coherent system, choose coherence.

When choosing between copying the prototype literally and preserving its intent, preserve the intent: an interactive professional tool that feels distinctly Ben's.
